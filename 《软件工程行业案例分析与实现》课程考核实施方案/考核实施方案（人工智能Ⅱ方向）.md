# 软件工程行业案例分析与实现考核实施方案

**适用方向：**人工智能Ⅱ方向　　**课程编号：**00014982　

## 一、成绩构成

满分 100 分，个人总成绩计算如下：

**个人总成绩＝课堂表现（30）＋平时作业（20）＋所在小组作品（25）＋本人项目答辩及报告（25）**

| 考核项目 | 分值 | 评分对象 |
| --- | ---: | --- |
| 课堂表现 | 30 | 个人 |
| 平时作业 | 20 | 个人 |
| 小组作品 | 25 | 小组，组内共享 |
| 项目答辩及报告 | 25 | 个人 |

## 二、学生提交内容

### 1. 小组统一提交

按以下结构提交一个完整项目包，文件夹和压缩包均命名为“`系统名称-组长班级-组长姓名`”。

```text
系统名称-组长班级-组长姓名/
├─ README.md                      # 一页运行说明
├─ 小组报告-系统名称.pdf
├─ 成员任务表.xlsx
├─ 选题登记表.xlsx                 # 2个感知模块＋1个扩展能力
├─ 测试结果.xlsx                   # 正常、异常测试用例及结果
├─ src/                            # 前端、后端及配置文件
├─ config/                         # 运行配置模板；API密钥不得写入
├─ data/测试数据/                   # 小组自备的音频、图像、文本、简历等测试材料
├─ evidence/                       # 验收证据
│   ├─ 构建或自动化测试记录.txt
│   ├─ 关键接口返回.json
│   └─ 运行截图或录屏/
└─ 个人材料/
    ├─ 作业01-学号-姓名-需求与方案分析.pdf
    ├─ 作业02-学号-姓名-Vue3页面与交互.zip
    ├─ 作业03-学号-姓名-SpringBoot接口数据权限.zip
    ├─ 作业04-学号-姓名-测试及项目风险分析.xlsx
    ├─ 软件班级-姓名-个人报告.pdf
    └─ 软件班级-姓名-工作证据/       # Git提交、接口测试记录、测试报告、设计文档等
```

**README.md 至少写明：**

1. 项目版本号、前后端启动命令、依赖版本；
2. 演示账号及登录入口；
3. 所选 2 个感知模块和 1 个扩展能力的名称、操作入口；
4. 每项功能对应的测试输入、预期结果和实际结果；
5. 外部模型或服务的名称与调用方式，配置项填写占位符，不得包含真实 API 密钥。

**选题范围：**

- 感知模块二选一：从“语音分析、视觉行为分析、文本理解与评价”中任选 2 项；
- 扩展能力一选一：从“简历与题目、大模型面试官、实时面试间”中任选 1 项；
- 所选 2 个感知模块必须接入评分引擎，并生成能够追溯输入数据的评测报告。

### 2. 学生个人提交

四项平时作业由学生本人独立提交，统一放入 `个人材料`。文件名使用“作业编号-学号-姓名-作业名称”。

| 材料 | 提交文件 | 文件说明 |
| --- | --- | --- |
| 作业1 | `作业01-学号-姓名-需求与方案分析.pdf` | 说明项目角色、主要业务流程、数据对象、所选 AI 功能和方案选择。 |
| 作业2 | `作业02-学号-姓名-Vue3页面与交互.zip` | 提交一个可运行的 Vue3 页面与交互代码，并附 `运行说明.md`。 |
| 作业3 | `作业03-学号-姓名-SpringBoot接口数据权限.zip` | 提交 Spring Boot 接口、数据和权限代码，并附数据库脚本及 `API清单.md`。 |
| 作业4 | `作业04-学号-姓名-测试及项目风险分析.xlsx` | 提交测试用例及执行结果、项目风险及应对措施。 |
| 个人报告 | `软件班级-姓名-个人报告.pdf` | 说明本人负责的设计、代码、测试、成果位置及个人结果。 |
| 工作证据 | `软件班级-姓名-工作证据/` | 放入 Git 提交、接口测试记录、测试报告、设计文档或验收截图等可定位证据。 |
| 本人答辩 | 不单独提交文件 | 现场展示 1 项本人完成的成果，并说明实现位置。 |
### 3. 接收条件

项目包须同时满足以下条件，缺项对应评分项不得记满分：

1. 命名、目录和材料齐全；
2. 代码可获取，README 可指导启动；
3. 测试数据与现场输入有效；
4. 任务表、个人报告和工作证据能够对应到具体成员；
5. 不含真实 API 密钥、真实个人隐私数据或其他未授权数据。

## 三、统一核验方法

### 1. 材料预检

教师按下表核验，统一使用“通过／部分通过／不通过”记录。

| 序号 | 检查项 | 通过标准 | 核验证据 |
| --- | ---: | --- | --- |
| 1 | 文件完整性 | 所列目录、代码、说明、报告、任务表和个人材料齐全 | 文件清单 |
| 2 | 可运行性 | 按 README 能启动项目并登录 | 启动日志、运行截图 |
| 3 | 版本一致性 | 项目包中的代码、报告和证据对应同一版本 | 版本号、提交记录 |
| 4 | 成员贡献对应 | 任务表、个人报告、工作证据能相互对应 | 任务表与个人材料 |
| 5 | 数据与密钥安全 | 无真实密钥、隐私数据或无关数据 | 配置文件检查记录 |

### 2. 小组现场验收

每组 12～15 分钟，各组按同一顺序操作：

| 顺序 | 现场操作 | 合格判据 |
| ---: | --- | --- |
| 1 | 启动系统，以候选人身份预约面试，刷新查询；切换 HR／管理员查看记录 | 登录、预约、存储和角色查询全部走通 |
| 2 | 分别输入一份新的音频、图像或文本 | 2 个感知模块均处理新输入并返回真实结果 |
| 3 | 现场触发选定的扩展能力 | 简历组卷、大模型问答或 WebRTC 面试间中所选功能可运行 |
| 4 | 查看由 2 个感知结果生成的评测报告 | 报告能追溯输入和评分规则；未测维度显示“未评估” |
| 5 | 输入非法数据或执行越权访问 | 有明确异常或权限拦截，结果可复现 |
| 6 | 抽查架构、测试、部署材料 | README、测试记录、架构和小组报告与现场状态一致 |

### 3. 个人答辩

每人 3～4 分钟：

1. 指出本人负责的代码或文档位置；
2. 现场演示 1 项本人完成的成果；
3. 回答 1 个本人工作的实现逻辑问题；
4. 回答 1 个与本人工作相关的测试、权限、异常或技术取舍问题。

### 4. 真实实现判据

现场换用新的输入后，系统实际调用算法、模型或外部 AI 服务并完成接口集成，方视为真实实现。

以下情况按“无法核验”处理：固定 JSON、写死分数、只有截图或说明、报告与输入不对应、无法复现。教师以现场操作结果为第一依据，其次核对日志、测试记录和报告。

## 四、评分标准

### 1. 课堂表现（30 分）

| 评分项 | 分值 | 满分条件 | 中间档 | 0 分 |
| --- | ---: | --- | --- | --- |
| 到课与课堂纪律 | 8 | 按要求到课，无违纪，课堂记录完整 | 6 分：有迟到、早退或轻微违纪，未影响任务 | 0 分：无故缺席、拒绝参与或严重违纪 |
| 前端检查 | 4 | 检查时能独立展示并说明所负责页面或接口 | 2 分：完成主要任务，但需提示或存在明显缺项 | 0 分：未完成或无法展示 |
| 后端检查 | 4 | 检查时能独立展示并说明所负责接口或数据处理 | 2 分：完成主要任务，但需提示或存在明显缺项 | 0 分：未完成或无法展示 |
| 联调检查 | 4 | 检查时能完成前后端联调并解释异常 | 2 分：可运行但处理不完整 | 0 分：未完成或无法展示 |
| 讨论、问答与代码评审 | 6 | 能提出问题、参与讨论并完成有效评审 | 3 分：有参与但说明或评审较浅 | 0 分：未参与 |
| 分工任务履行 | 4 | 按任务表完成本人阶段任务并提交记录 | 2 分：主要任务完成，部分记录不全 | 0 分：未履行或记录无法对应本人 |

### 2. 平时作业（20 分）

四项作业分别独立评分。5 分项按 **5／3／0**，7 分项按 **7／4／0**，3 分项按 **3／1／0**。

| 作业 | 分值 | 满分要求 |
| --- | ---: | --- |
| 作业1：需求与方案分析 | 5 | `作业01-学号-姓名-需求与方案分析.pdf` 包含角色与目标、完整业务流程、至少 2 个核心数据对象、所选 AI 功能验收标准和架构方案理由；随机抽查内容能够追溯到后续实现 |
| 作业2：Vue3 页面与交互 | 5 | `作业02-学号-姓名-Vue3页面与交互.zip` 可运行；完成 1 个核心页面和 1 条用户交互流程，包含接口调用、状态处理、表单校验、加载／空数据／错误状态；运行说明有效 |
| 作业3：Spring Boot 接口、数据与权限 | 7 | `作业03-学号-姓名-SpringBoot接口数据权限.zip` 可运行；至少 3 个关联接口、2 个持久化数据表或实体、2 种角色权限，包含参数校验、异常返回及数据库脚本；`API清单.md` 与实际接口一致 |
| 作业4：测试及项目风险分析 | 3 | `作业04-学号-姓名-测试及项目风险分析.xlsx` 含 3 条正常、2 条异常、1 条权限测试及执行证据，另含 5 条触发条件、影响、应对措施、责任人和状态完整的项目风险 |

### 3. 小组作品（25 分，组内共享）

| 检查项 | 分值 | 满分条件 |
| --- | ---: | --- |
| 共同业务闭环 | 4 | 登录、预约、存储、换角色查询走通，前后端与数据库真实联动 |
| 感知模块一 | 4 | 所选第一项能处理新输入并返回真实结果 |
| 感知模块二 | 4 | 所选第二项能处理新输入并返回真实结果 |
| 扩展能力 | 4 | 所选扩展能力可现场运行 |
| 融合评分与报告 | 3 | 2 个感知结果进入评分规则，报告可追溯，未测维度处理正确 |
| 架构与质量 | 3 | 架构、数据模型和接口设计合理，有正常及异常测试证据 |
| 部署与小组报告 | 3 | 能按 README 运行，有构建或自动化测试记录；报告完整说明需求、实现、分工、测试和风险 |

评分规则：4 分项按 **4／2／0**，3 分项按 **3／1／0**。

### 4. 项目答辩及报告（25 分）

| 检查项 | 分值 | 满分条件 |
| --- | ---: | --- |
| 个人贡献 | 5 | 任务表、提交或测试记录与本人实际成果一致 |
| 成果讲解 | 5 | 能指出并解释本人关键实现，现场展示成功 |
| 实现逻辑问答 | 5 | 能说明本人工作的业务逻辑、数据流或接口实现 |
| 工程问题问答 | 5 | 能分析相关测试、权限、异常、数据安全或技术取舍 |
| 个人报告及互评 | 5 | 个人报告 3 分；组内互评 2 分，均经教师核实 |

前四项按 **5／3／0**；个人报告和互评分别在 3 分、2 分内据实评分。互评与任务记录或实际成果不一致时，以教师核实结果为准。

### 5. 评分统一规则

| 结论 | 记分规则 | 判定 |
| --- | --- | --- |
| 满分 | 4 分项记 4，3 分项记 3，5 分项记 5，7 分项记 7 | 功能现场可运行，要求完整，证据有效 |
| 中间档 | 4 分项记 2，3 分项记 1，5 分项记 3，7 分项记 4 | 有实际成果，但存在未集成、不稳定或材料不完整 |
| 0 分 | 记 0 | 缺失、无法核验或以写死结果冒充真实结果 |

补充规则：

1. 未达满分的检查项只记 1 个简短原因，不再重复扣分；
2. 缺少某项材料时，仅该项目按 0 分处理，不另设材料缺失扣分；
3. 不按代码行数、模型名称或技术路线加分，按同一功能结果评分；
4. 小组作品分由组内成员共享，个人差异在课堂、作业和答辩项中体现。
