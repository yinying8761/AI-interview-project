# 项目运行说明

## 1. 项目信息

- 项目名称：多模态智能模拟面试评测平台
- 项目版本号：v1.1.0（源码版本 `30d718a`）
- 提交日期：2026-10-16
- 组长：郑颖浩　成员：常辰、赵佳伟

## 2. 运行环境

- 操作系统：Windows 11（专业版）
- Node.js 版本：18 及以上（实测 v24.15.0，npm 12.0.2）
- Java 版本：JDK 21（实测 21.0.5 LTS），Maven 3.9.9
- 数据库版本：演示模式使用内置 H2 2.1.214（持久文件，免安装）；可选 MySQL 8.0.46
- 其他依赖：Redis 7（演示占用 DB 11）、Python 3.10（AI 能力服务）、DeepSeek 开放平台账号

## 3. 启动方式

### 后端

```text
# 第一步：启动 AI 能力服务（端口 8765），需先配置 .env 中的 DEEPSEEK_API_KEY
cd smartspeech_optimized
python -m backend.run

# 第二步：构建并启动 Java 主后端
cd interview-ai
mvn -B -ntp package
java -jar interview-bootstrap/target/interview-bootstrap-1.0.0.jar --spring.profiles.active=dev,demo
```

```text
说明：--spring.profiles.active=dev,demo 使用内置 H2 演示库，首次启动自动建表并导入
     演示账号，无需安装 MySQL；接口文档 http://127.0.0.1:8080/doc.html
     如需改用 MySQL：先执行 interview-ai/sql/interview_ai.sql 建库，
     复制 application-local.yml.example 为 application-local.yml 填写数据库口令，
     再以 --spring.profiles.active=dev,local 启动。
```

### 前端

```text
cd interview-ai/frontend
npm ci
npm run dev
访问地址：http://localhost:5173
```

```text
说明：开发服务器默认把 /api 代理到 http://localhost:8080，与上面后端默认端口一致；
     若后端改到其他端口，启动前设置 $env:API_PROXY_TARGET='http://127.0.0.1:端口号'
```

## 5. 所选 AI 功能

| 类型 | 功能名称 | 操作入口 | 测试输入 | 预期结果 |
| --- | --- | --- | --- | --- |
| 感知模块一 | 文本理解与评价 | 登录候选人 → 面试大厅选择场景与“大模型面试官（文本＋视觉）” → 生成首题 → 文本作答 → 提交 | 一段**新的**岗位回答（见 `data/测试数据/新文本回答.txt`） | 调用 DeepSeek 对真实题面与作答逐题评估，返回真实问答得分与逐题点评 |
| 感知模块二 | 视觉行为分析 | 面试间开启摄像头，保持面部可见约 15 秒以上 → 完成面试 | **新的**图像输入（见 `data/测试数据/合成面试人像.png`，虚构人物） | MediaPipe FaceMesh 采集面部关键点，输出表情分、注意力分与视觉汇总 |
| 扩展能力 | 大模型面试官 | 面试间“生成首题”，随后连续作答触发追问 | 任意一场新建面试 | 大模型按岗位与简历生成开场题，并根据作答内容追问；会话状态可查询 |
| 评分报告 | 两项感知结果接入评分引擎 | 我的记录 → 查看报告 | 完成一场同时含问答与视觉样本的面试 | 综合分 ＝ 问答×0.8＋(表情×0.5＋注意力×0.5)×0.2；报告保存输入原文、逐题评估、公式与各维度状态，可追溯输入和评分规则 |

## 6. 测试与异常处理

| 测试场景 | 测试输入 | 操作步骤 | 预期结果 | 实际结果 |
| --- | --- | --- | --- | --- |
| 正常业务流程 | `test01` / `123456` | 登录 → 预约面试 → 刷新查询 → 切换 HR／管理员查看记录 → 进入面试 → 作答 → 查看报告 | 登录、预约、存储、换角色查询全部走通 | **通过**（`tools/smoke_test.py` 22/22，含落库与三角色查询） |
| 感知模块真实结果 | 新的文本回答 ＋ 合成人像 50 帧 | 提交新回答，逐帧送入人像图像 | 两个感知模块均返回真实结果 | **通过**（问答 45.0；表情＋注意力 65.0；综合 45.0×0.8＋65.0×0.2＝49.0） |
| 非法输入 | 空密码、不存在的场景 ID、重复时间段的预约 | 直接调用对应接口 | 参数校验或业务异常明确返回 | **通过**（空密码、场景不存在、预约冲突均被拦截） |
| 权限或越权访问 | 未登录令牌、他人 recordId、管理员冒充候选人预约 | 直接调用对应接口 | 明确拦截并返回 401／403 | **通过**（未登录、他人记录详情、他人状态快照、越权创建均被拦截） |
| 未测维度处理 | 不开启摄像头完成面试 | 完成面试后查看报告 | 视觉维度显示“未评估”，不给出综合分 | **通过**（visionStatus＝未评估，finalScore 为空） |

## 7. 外部模型或服务

- 模型或服务名称：DeepSeek Chat（模型 `deepseek-chat`）
- 调用方式：Java 主后端 → Python AI 能力服务 `http://127.0.0.1:8765/api/ai/*` → HTTPS 调用 DeepSeek 开放平台；密钥仅保存在 AI 服务侧
- 配置占位符：`DEEPSEEK_API_KEY=<在此填写自己的密钥>`，写入 `smartspeech_optimized/.env`（该文件不随项目提交，模板见 `.env.example`）
- 测试输入：任意一段新的岗位回答文本

> 真实 API 密钥不得写入 README、源代码、配置文件或任何提交材料。
