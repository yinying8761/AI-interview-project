# 学生提交材料目录内容说明

本模板用于《软件工程行业案例分析与实现》人工智能Ⅱ方向课程验收。

## 使用方法

1. 将 `系统名称-组长班级-组长姓名` 目录复制或重命名为实际的项目根目录。
2. 按下表补齐小组统一提交的文件和目录。
3. 将每位成员的个人报告和个人工作证据放入 `个人材料`。
4. 检查无真实 API 密钥、真实个人隐私数据或无关数据。
5. 压缩时以重命名后的项目根目录作为压缩包第一层。

## 项目根目录

`系统名称-组长班级-组长姓名/`

## 提交清单

| 文件或目录 | 需要提交的内容 | 要求 |
| --- | --- | --- |
| `README.md` | 项目版本、依赖、启动命令、演示账号、所选 AI 功能、测试输入和操作入口 | 一页内说明清楚，能够指导教师启动和核验 |
| `小组报告-系统名称.pdf` | 需求、架构、实现、分工、测试和风险 | 与提交版本一致 |
| `成员任务表.xlsx` | 成员姓名、学号、分工、成果位置 | 任务记录能够对应到个人成果 |
| `选题登记表.xlsx` | 2 个感知模块、1 个扩展能力及接入评分报告的说明 | 开题时确定，结课时保持一致 |
| `测试结果.xlsx` | 正常、异常和权限相关测试用例及结果 | 结果真实，可定位到测试数据 |
| `src/` | Vue3 前端、Spring Boot 后端、运行配置模板及相关源代码 | 提交带版本标识的实际项目代码 |
| `config/` | 配置模板、接口地址和公开参数 | API 密钥使用占位符，不得提交真实密钥 |
| `data/测试数据/` | 用于验收的音频、图像、文本、简历或业务数据 | 使用模拟或经授权数据 |
| `evidence/` | 构建或自动化测试记录、关键接口返回、运行截图或录屏 | 能够佐证现场实际运行结果 |
| `个人材料/软件班级-姓名-个人报告.pdf` | 本人负责的需求、设计、代码、测试及成果位置 | 每人独立提交 |
| `个人材料/软件班级-姓名-工作证据/` | Git 提交、合并请求、接口测试记录、测试报告、设计文档或验收截图 | 至少提供 1 项可定位证据 |

## 选题要求

- 感知模块二选一：从“语音分析、视觉行为分析、文本理解与评价”中任选 2 项。
- 扩展能力一选一：从“简历与题目、大模型面试官、实时面试间”中任选 1 项。
- 所选 2 个感知模块必须接入评分引擎，并生成能够追溯输入数据的评测报告。

## 提交前检查

按 README 能够启动项目和登录；代码、报告、测试结果及个人证据版本一致；所选功能均配有新的验收测试输入；文件和成员材料齐全；不含真实密钥、真实个人隐私数据或无关数据。
